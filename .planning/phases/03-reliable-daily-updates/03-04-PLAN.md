1. Expectation checkpoint — confirm with the user the honest meaning of "daily" (stalest-first slice daily + weekly full sweep + per-route freshness), so DAILY-01 success is judged against the right bar (CONTEXT: surface this expectation in a checkpoint).

3. Human-verify checkpoint — trigger ONE manual workflow_dispatch of the daily workflow, then MEASURE the block rate from scanner stats, and decide whether to enable the daily cron, reduce frequency, or defer (CONTEXT: the big unknown).

Purpose: turn the locally-proven code into an actually-running daily refresh, without walking into a Google block blind.
Output: pushed repo + Secrets, a measured block-rate reading, and a recorded cron decision (cron enabled in scan.yml only if measurement is green).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local working tree -> GitHub remote | A push could leak secrets if .env-like files were staged |
| GitHub Secrets store -> Actions runtime | The secret key lives in GitHub; exposure via logs is the risk |
| GitHub shared Azure IP -> Google Flights | The block-risk boundary being measured |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-10 | Information Disclosure | secrets entering git on push | mitigate (blocking-human) | Mandatory pre-push secret-scan: confirm .env + web/.env.local gitignored AND untracked, grep diff for sb_secret_/ANTHROPIC/SUPABASE_SECRET/token; checkpoint blocks until clean (鐵律 1) |
| T-03-11 | Information Disclosure | secrets pasted into chat/commit | mitigate | Secrets are set ONLY in GitHub Secrets UI by the user; values never requested in chat; workflows read via ${{ secrets.* }} |
| T-03-12 | Denial of Service | enabling daily cron blind -> Google block | mitigate (blocking-human) | Cron stays off until the dispatch run's measured block rate is reviewed; enabling is a human decision, never auto |
| T-03-13 | Repudiation | unknown whether partial-publish actually fired | mitigate | The dispatch checkpoint explicitly verifies the if: always() upload step ran on a failed shard (DAILY-03 live proof) |
